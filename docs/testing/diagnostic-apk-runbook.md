# Local diagnostic APK: build, installation, rollback

**Scope:** engineering-only application for the Hisense 58U6HF running Fire OS 7. This does not replace the OpenVista player, system launcher, or screensaver. Do not upload the APK to GitHub Releases without owner approval.

## Identity and safety

- Application ID: `com.openvista.diagnostics`.
- Launcher label: OpenVista Device Check.
- Minimum API: 28 (Android 9). Compile/target SDK: 36.
- No requested Android permissions, Internet access, media files, bundled stream URLs, boot receivers, background services, or content providers.
- No hardware or file inspection runs before a user presses **Run Device Check**.
- JSON output is written only after **Export JSON**, a confirmation dialog, and successful user interaction with `ACTION_CREATE_DOCUMENT`.
- A report contains device manufacturer/model, API/OS, supported ABIs, display modes/HDR, advertised decoders, RAM/storage estimates, picker availability, and check states. Never include serials, raw Android fingerprints, account names, media URIs, LAN addresses, or pathnames.

## Reproduce the local build on Windows

Requires JDK 17+ (tested with Temurin 21), Android SDK platform 36, build-tools 36, and local Gradle Wrapper 8.13. Use the Android SDK installed on the workstation.

```powershell
cd I:\codex\openvista
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
.\gradlew.bat :diagnostics:assembleDebug :diagnostics:testDebugUnitTest :diagnostics:lintDebug --no-daemon
```

APK: `diagnostics/build/outputs/apk/debug/diagnostics-debug.apk`. The local debug keystore is generated by Android Gradle tooling. This is **not** a public release signing identity. Keep the debug keystore private and use a separately managed, stable key before any public release.

Review the actual artifact using SDK build tools:

```powershell
$apk = "diagnostics\build\outputs\apk\debug\diagnostics-debug.apk"
& "$env:ANDROID_HOME\build-tools\36.0.0\aapt.exe" dump permissions $apk
& "$env:ANDROID_HOME\build-tools\36.0.0\apksigner.bat" verify --verbose $apk
```

## Authorized one-app installation

Only install when the owner authorizes device use. Confirm the serial-free package listing first. Use an isolated package ID; do not uninstall, update, or stop unrelated installed packages.

```powershell
adb devices -l
adb shell pm list packages com.openvista.diagnostics
adb install -r diagnostics\build\outputs\apk\debug\diagnostics-debug.apk
adb shell am start -n com.openvista.diagnostics/.DiagnosticsActivity
```

The `-r` option **updates this same diagnostic package** without installing a second OpenVista app. Before testing another *different* app package, remove this one, consistent with the device owner's one-app rule.

## Manual hardware test

1. Open the diagnostic app manually. Confirm that it shows an idle state with no collection on startup.
2. Use only D-pad/OK to focus **Run Device Check** and inspect device/display/codec/picker information.
3. Focus **Export JSON**. Verify the warning/consent dialog appears. Cancel it to verify no file is created.
4. Approve export and choose a destination using the system document picker. On the Hisense, an ADB **touchscreen** tap on the system Save button was confirmed to complete this action. The OEM picker Save button has **not** been confirmed D-pad reachable, so do not imply a physical remote-only save works. Validate the exported report, without printing private content: `python -m pip install jsonschema==4.25.1`, then `python scripts/validate_diagnostic_report.py PATH_TO_EXPORTED_JSON`. Never commit the exported report.
5. Press Back/Exit. Verify the existing launcher, other apps, and their settings remain unchanged.
6. Mark codec resolution, USB picker access, sustained 4K playback and DreamService as *unverified* until separate real-device tests prove them.

## Rollback

```powershell
adb uninstall com.openvista.diagnostics
adb shell pm list packages com.openvista.diagnostics
```

Only uninstall the package above. Removing the app does not require or justify changing the OEM screensaver, default launcher, ADB settings or any unrelated app. Any intentionally exported JSON file is user-owned and is **not** automatically deleted by app uninstallation.
